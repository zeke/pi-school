If you find yourself typing the same kind of prompt over and over — "summarize this project", "review my changes", "explain this file" — prompt templates let you save that prompt and run it with a single slash command.

Type `/` in the input and you'll see a list of available templates and built-in commands together, with descriptions in autocomplete.

## Defining a prompt template

Prompt templates are Markdown files. Pi loads them from `~/.pi/agent/prompts/*.md` (global, available in every project) or `.pi/prompts/*.md` (project, loaded once the project is trusted). The filename becomes the command name.

`~/.pi/agent/prompts/summarize.md`:

```markdown
---
description: Summarize the current project
---
Give me a brief overview of this project. What is it? What are the main files and folders? What does it seem to be for?
```

Now you can run `/summarize` in any Pi session. `description` is optional — if you leave it out, Pi uses the first non-empty line of the body instead.

## Try it: create a /summarize template

Ask Pi to create the file `~/.pi/agent/prompts/summarize.md` with the content above.

Run `/reload` afterward to pick it up — no restart required. Then type `/summarize` in the input; you should see it in the autocomplete list. Select it and hit Return to run it.

## Passing arguments

Templates support positional arguments, defaults, and slicing:

| Syntax | Meaning |
|---|---|
| `$1`, `$2`, ... | Positional arguments |
| `$@` or `$ARGUMENTS` | All arguments, joined |
| `${1:-default}` | Argument 1, or `default` if it's missing or empty |
| `${@:N}` | All arguments starting from position `N` (1-indexed) |
| `${@:N:L}` | `L` arguments starting from position `N` |

For example:

```markdown
---
description: Create a component
---
Create a React component named $1 with features: $@
```

Run it as `/component Button "onClick handler" "disabled support"` and `$1` becomes `Button` while `$@` becomes the full argument list.

Defaults are handy for optional arguments:

```markdown
Summarize the current state in ${1:-7} bullet points.
```

## Argument hints

Add `argument-hint` to a template's frontmatter to show what arguments it expects, right in autocomplete. Use `<angle brackets>` for required arguments and `[square brackets]` for optional ones:

```markdown
---
description: Review PRs from URLs with structured issue and code analysis
argument-hint: "<PR-URL>"
---
```

This shows up in autocomplete alongside the description, so you don't have to remember a template's expected arguments.

Prompt templates in Pi are Markdown-only — there's no alternate JSON format, and no way to pin a template to a specific agent or model. Keep templates focused on the prompt text itself.
